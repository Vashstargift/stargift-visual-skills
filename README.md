# StarGift Visual Skills — оформление экспонатов и премиум-презентации

Передаточный набор двух навыков Claude Code для StarGift (stargift.ru), собран 30.07.2026.
Эти навыки живут в Telegram-боте «Док» (менеджеры пользуются ими по-русски, без команд),
но код самодостаточен — его можно подключить к любому агенту.

## Состав

| Папка | Что внутри |
|---|---|
| `framing/` | Навык 1: оформление фото экспонатов по эталонам (рамы, packshot, композиты, гравировка шильдов) |

## Навык 1. Оформление фото экспонатов (`framing/`)

**Задача:** реальное фото экспоната → красивый каталожный вид: рама с паспарту, чистый
студийный фон (packshot) или кино-композит. Сам предмет НИКОГДА не перерисовывается —
меняется только окружение; автографы обязаны сохраняться пиксельно.

### Архитектура

- `framing_tool.py` — весь конвейер:
  - `frame_exhibit_photo(photo_path, person_latin, style_notes, frame_style)` — оформление одного фото;
  - `frame_cinema_composite(item_path, poster_path, person_latin)` — кино-композит ПО ШАБЛОНУ (без генерации, мгновенно);
  - `_engrave_shield()` — локальная гравировка шильда «PERSONALLY SIGNED BY / ИМЯ» (PIL по пустой пластине);
  - авто-трим пустых полей фона вокруг рамы.
- `framing_styles.json` — **единственный источник правды по рамам.** Каждый стиль: prompt,
  реф-фото (реальные оформления с витрины!), список категорий `for`, опционально `plate_zone`
  (где искать пластину) и `packshot: true` (замена только фона, без рамы и шильда).
- `higgsfield_client.py` — клиент генерации (модель `nano_banana_2` через Higgsfield MCP).
  Ключей в коде нет: авторизация — MCP-сервер higgsfield в конфиге агента.
- `refs/` — эталонные фото. `sources.json` — из каких карточек сайта взят каждый эталон.

### Утверждённые стили (Вашик, 30.07.2026)

Выбор — ПО ТИПУ/ТЕМАТИКЕ экспоната, выдумывать рамы ЗАПРЕЩЕНО:

| Ключ | Что это | Для чего |
|---|---|---|
| `brand` | чёрная рама + синее паспарту с золотой окантовкой | спорт-фото, универсальный |
| `photo-strict-dark` | строгая тёмная рама БЕЗ паспарту | кино-кадры, портреты актёров |
| `photo-brown-velvet` | коричневая + бордовый бархат | музыка, рок |
| `retro-gold-baroque` | золотая резная + бордовый бархат | дорогое ретро, Голливуд, королевские особы |
| `retro-silver-pearl` | серебристо-жемчужная + синий бархат | ретро-актрисы, ч/б |
| `tshirt-black-flat` | чёрная плоская рама-короб | футболки, джерси |
| `historic-brown-gold` | коричневая с золотым кантом | исторические, литографии, документы |
| `historic-silver-blue` | серебристая + синий бархат | наука, космос |
| `vinyl-gold-velvet` | золотая фактурная + бархат в тон обложки | пластинки |
| `glass-float` | между стёкол, без паспарту | постеры, афиши, документы |
| `packshot-white` | чистый белый студийный фон | каталожная подача предметов (эталон — бутса CR7) |
| `packshot-black` | глубокий чёрный + контровая подсветка | дорогие предметы в премиум-деках (кубок, скакалка, кроссовки) |
| `cinema-composite` | предмет + постер фильма в одной раме | дорогие кино-лоты; работает ПО ШАБЛОНУ (см. ниже) |

Соседние фото-экспонаты в одной подборке — в РАЗНЫХ стилях (два одинаковых паспарту рядом = однообразно).

**Вариации внутри стиля (Вашик, 30.07):** ЦВЕТ паспарту и рамы можно менять — в тон
экспоната, под клубные цвета, по просьбе менеджера (свободным текстом в `style_notes`);
сам ТИП рамы — только из таблицы выше. Шильды по умолчанию золотые; для серебристых рам
и холодной гаммы — СЕРЕБРЯНЫЕ (`"shield": "silver"` в стиле — уже стоит у
historic-silver-blue и retro-silver-pearl; разово — `style_notes: «серебряный шильд»`).
Гравировка и генерация подхватывают цвет автоматически (детектор пластины умеет обе).

### Железные правила

1. **Шильд всегда прямоугольный** с прямыми углами, всегда с именем (латиницей; команда —
   названием команды). Обычно золотой, для серебристых рам/холодной гаммы — серебряный.
   Имя НЕ отправляется генератору — гравируется локально (блокировок не бывает).
2. **Фото целиком** — не обрезать края кадра; окно паспарту подстраивается под пропорции.
3. **Кино-композит = шаблон, не генерация:** сцена (рама/бархат/окна/мольберт) — фиксированный
   файл `composite-template-burgundy.jpg` с вымеренными окнами (`win_left/win_right/plate_box`
   в styles); реальные фото вклеиваются попиксельно → тексты и автографы идеальны по построению,
   сборка мгновенная и бесплатная.
4. Оформляющее (сопроводительное) фото: (а) из уже оформленного экспоната той же персоны,
   (б) поиск по интернету (узнаваемый образ человека). НЕ дублировать фото самого экспоната.

### Гочи (кровью выстраданы 30.07)

- Детектор пластины ищет «золото» по цвету — **тёплые тона на самом фото (бежевый пиджак!)
  проходят фильтр**. Поэтому зона поиска ограничена нижней полосой (`plate_zone`), у стилей
  без паспарту — нижней планкой рамы (y от 0.90).
- Хромакей-подход для композитов (зелёные окна в генерации) НЕ работает — генератор мажет
  зелёным за границы. Только шаблонная вклейка.
- Генератор перерисовывает мелкий текст с опечатками — поэтому постеры/сценарии в композите
  вклеиваются локально, а не генерируются.
- Относительные пути фото в каталоге (`/media/...`) — добавлять домен; не-ASCII в URL — квотить.
- У генераций остаются поля студийного фона → авто-трим; мягкий градиент требует иногда
  жёсткого порога (см. `_cover_crop`/трим в `framing_tool.py`).

## Навык 2. Премиум-презентации (`premium-deck/`)

**Задача:** кинематографичная презентация-подборка для VIP-клиентов: обложка с архивным
кадром, разделы с подводками, карточки лотов, витрина «Готовы к передаче», слайды
оформления/доставки/контактов. Выход: PDF (Chrome print) + редактируемый PowerPoint → Keynote.

### Архитектура — ДВА рендера, правки вносить В ОБА

1. **PDF**: `constructor.html` (SG_API.build) → Chrome headless → PDF. Шаблоны слайдов — функции
   `TPL.*` внутри constructor.html.
2. **Редактируемая версия**: `presentation_pptx.py` (python-pptx) — СВОЯ вёрстка тех же слайдов;
   затем конвертация .pptx → .key через Keynote.app (AppleScript, см. `deps/selection_pptx.py::convert_to_key`).

`presentation_v2.py` — оркестратор: данные лотов → constructor → PDF → отправка → pptx → key →
отправка → сохранение состояния (`load_last_state`) для последующих правок «поправь слайд 4».

- `SKILL.md` — рабочая инструкция бота: как собирать состав, разделы, обложку, тексты,
  правила дома, принятые правки команды. ЧИТАТЬ ПОЛНОСТЬЮ перед использованием.
- `etalon-legendy-kino-v2-final.pdf` — утверждённый эталон (30.07): светлый информативный
  режим, вдумчивые описания, предметы на чёрном packshot, кино-фото в строгих рамах.

### Ключевые правила вёрстки (в обоих рендерах)

- Текст обрезается ТОЛЬКО по границе предложения (`fitSent`/`_fit_sent`) — «…» посреди фразы запрещены.
- Несколько фото на слайде — ОДНОГО размера, нижняя грань на общей линии.
- Подписи карточек центрированы; имя/тип/описание в зоне фиксированной высоты →
  цена/размеры/наличие у всех карточек слайда на одном уровне.
- Витрина «Готовы к передаче» не забирает лот, если его раздел опустеет (иначе «Состав
  собрания» обещает главу, которой нет).
- Без счётчиков экспонатов и «Итога собрания» — суммы отталкивают клиентов.
- Описания НЕ пересказывают название лота: сразу о человеке и предмете, 3–4 спокойных
  предложения (режим по запросу; базовый режим — лаконичный, desc пустой у самоочевидных).
- Формулировка «Сертификат подлинности галереи StarGift» разрешена в сервисных блоках,
  в текстах лотов тема подлинности запрещена.

## Зависимости и адаптация

**Python (venv):** Pillow, python-pptx, playwright (или системный Chrome), fontTools (для
диагностики шрифтов), pymupdf (для проверки PDF).

**Внешнее:** Higgsfield MCP (генерация, модель nano_banana_2); Telegram Bot API (токен в
`.env` профиля, читается `deps/selection_sender.py`); Keynote.app (конвертация .key, macOS);
Google Chrome (PDF-рендер).

**Шрифты НЕ включены** (лицензия): Proxima Nova (гравировка шильдов — пути в
`framing_tool.py: _FONT_FILES`) и Prata/Golos Text (веб-шрифты презентаций). ВАЖНАЯ гоча:
в ходовых наборах Proxima Nova регулярный вес живёт семейством «Proxima Nova Rg», а в
семействе «Proxima Nova» регуляра нет вовсе — запрос регуляра рендерится жирным.

**Жёсткие пути под адаптацию** (грепать `/Users/docbrown`):
- `framing_tool.py`: `OUT_DIR`, `STYLES_FILE`, `_FONT_FILES`, `FRAMING_REF`
- `framing_styles.json`: пути refs → перенести на свои
- `presentation_v2.py`: `CONSTRUCTOR`, `STATE_DIR`
- `deps/selection_sender.py`: путь к `.env` с TELEGRAM_BOT_TOKEN
